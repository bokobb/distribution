# Дистрибуция

Система для компаний, которые развозят продукцию по магазинам: торговые агенты собирают заказы,
склад грузит машины, экспедиторы доставляют, берут оплату и забирают негодный товар.

Одна система обслуживает несколько компаний: собственную доставку производства и склады-дилеры
со своими директорами и командами. Данные каждой компании отделены. Владелец видит все компании,
а сводка выводится на главном экране CRM производства (`bokobb/CRM`).

## Что сейчас в репозитории

**Этап 1: база и вход.** Веб-админка работает на PostgreSQL, вход по телефону или логину.

| Раздел | Адрес | Что на странице |

## Запуск

Нужны Java 17+ и Docker.

```bash
cp .env.example .env        # заполните DB_PASSWORD, OWNER_PHONE, OWNER_PASSWORD (и DEMO_PASSWORD для демо)
docker compose up -d        # PostgreSQL 16 на 127.0.0.1:5436
./gradlew bootRun           # http://localhost:8090 — страница входа
```

Схему базы создаёт Flyway при запуске (`src/main/resources/db/migration`). Hibernate схему не
меняет, только сверяет с сущностями.

### Переменные окружения

Секреты — только в переменных окружения или в `.env` рядом с проектом (`.env` в git не попадает;
его читают и `docker compose`, и сервер).

| Переменная | Зачем |
|---|---|
| `DB_PASSWORD` | пароль базы (обязательно) |
| `DB_USER`, `DB_URL` | если база не та, что в `docker-compose.yml` |
| `OWNER_PHONE`, `OWNER_PASSWORD` | первый владелец: создаётся при запуске, если владельца в базе нет. При первом входе система попросит сменить пароль |
| `OWNER_NAME` | имя владельца (по умолчанию «Владелец») |
| `DEMO_PASSWORD` | пароль всех демо-сотрудников в профиле `demo` |

### Профили

- без профиля — пустая база: войти может владелец из `OWNER_PHONE`, дальше он создаёт компании
  (вместе с директором), директор — сотрудников, магазины и машины;
- `demo` — `./gradlew bootRun --args='--spring.profiles.active=demo'`: в пустую базу добавляются
  3 компании, 10 агентов, 5 экспедиторов, магазины, заказы, рейсы и касса. Демо-сотрудники входят
  с паролем `DEMO_PASSWORD`, телефоны — `+7 701 000 КК NN` (КК — номер компании, NN — порядковый:
  01 директор, 02 оператор, 03 кладовщик). Если в базе уже есть компании, демо-данные не добавляются;
- `local` — свои настройки этой машины в `src/main/resources/application-local.properties`
  (не в git, пример — `application-local.properties.example`).

Начать с чистой базы: `docker compose down -v && docker compose up -d` — **удаляет все данные базы**.

## GPS и журнал приложения

- Телефон торгового и экспедитора снимает точку GPS раз в N минут («Настройки», по умолчанию 5) и
  только в рабочий день: от «Начал день» до «Закончил день» в приложении. Сервер не сохраняет
  точки вне рабочего дня; не закрыл день — до конца той же даты.
- Журнал приложения: вход и выход, запуск, начал и закончил день, синхронизация, GPS выключен и
  включён — с версией приложения и моделью телефона.
- Телефон шлёт записи пачкой, когда есть сеть; повторная пачка дублей не создаёт.
- Точки GPS хранятся 6 месяцев, журнал — год: каждую ночь в 03:00 старше удаляются (`TrackCleanup`).
- Приём с телефона (`TrackService`) готов и покрыт тестами; адрес `/api` откроется вместе с
  приложением (этап 3) — там будет вход по токену.

## Вход и права

- Вход по телефону в любом виде (`8 701 …`, `+7 (701) …`) или по логину, если он задан.
- Директор, оператор и кладовщик работают в веб-админке; торговый агент и экспедитор — в приложении
  на телефоне (будет), в веб они не входят.
- Новому сотруднику выдаётся временный пароль — он показывается один раз. При первом входе
  система просит придумать свой. Забыл пароль — директор выдаёт новый.
- Компания сотрудника — из его профиля. Сервер не отдаёт записи чужой компании ни списками, ни по
  прямому адресу (ответ 404).
- Владелец выбирает компанию в шапке («Все компании» — сводно) и может открыть админку глазами
  другой роли («Смотреть как» в меню справа вверху); действия при этом записываются на него.

## Устройство

```
src/main/java/com/confectionery/distribution/
  domain/      сущности JPA; у записей компании — company_id (CompanyEntity, @TenantId)
  repository/  Spring Data JPA
  tenant/      какая компания открыта (TenantContext) — Hibernate сам фильтрует по ней все запросы
  service/     долги, склад (остатки только через движения), касса, формы и их проверка
  security/    вход: поиск сотрудника, первый владелец, страницы входа и смены пароля
  admin/       контроллеры страниц, меню по ролям (AdminSections), кто смотрит (AdminContext,
               TenantFilter), форматирование для шаблонов (Fmt → ${@fmt.money(x)})
  demo/        демо-данные (профиль demo)
src/main/resources/
  db/migration/         миграции Flyway
  templates/admin/      Thymeleaf-шаблоны админки, общий каркас — layout.html
  templates/            login.html, password.html
  static/admin/assets/  admin.css (палитра админки CRM), admin.js
  admin/icons.json      значки, как в CRM
```

Правила, которые держит код:

- деньги — целые тенге (`long`), количество — целые штуки, время — Asia/Almaty;
- долг магазина не хранится, а считается: начальный долг + выдано − оплачено − возвраты;
- остаток товара меняется только движением (приход, загрузка, выдача, возврат, разгрузка);
- ссылки между записями идут парой (id, company_id): база не примет ссылку на чужую компанию.

## Тесты

```bash
./gradlew build
```

Тесты поднимают PostgreSQL в Docker (Testcontainers): изоляция компаний (сервисы и страницы),
расчёт долга и просрочки, приём кассы и недостача, сохранение форм, вход и смена пароля, фильтры
и отгрузка заказов, карта, приём GPS (рабочий день, дубли), трек и пропажи GPS, очистка старых точек.
